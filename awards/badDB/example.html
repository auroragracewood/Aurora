BadDB — Snippet Template · Tier B master

Canonical reference for what badge snippets look like across all 9 representation form factors. This file is the master template — per-badge designs copy this structure into their own folder under designs/{year}/{badge-slug}/ and replace placeholders with that badge's artwork.

Two-tier architecture (locked 2026-05-08).
  • Tier A — Real Award Badges (Finalists + Winners): ONE exclusive portrait form factor, smart <script> embed, manual per-domain ceremony install. Designed in a separate pass — not here.
  • Tier B — Representation Badges (Starter, on-signup, applicant, etc.): the 9 form factors below, self-serve copy-paste snippets. This file is for Tier B only.
How to use this template. When we design a specific Tier B badge (Starter is first):
  1. Copy this example.html into designs/{year}/{badge-slug}/example.html
  2. Replace each form factor's placeholder SVG with that badge's actual SVG for that form factor
  3. Replace {kind}, {token}, {year}, {identifier} in the snippet samples with that badge's real values
  4. Add badge-specific notes / variations to that copy — leave THIS master file generic
Tier B design rules in progress (locked so far).
  • No URLs or slugs in the visual artwork. Verifier URL and recipient @slug do NOT appear in the rendered badge — those are part of the badge's click target (where clicking the badge takes the viewer), not part of what's drawn. (Revised 2026-05-08.)
  • Year splits to two parts on either side of the mark — pattern: [20 [mark] 26]. Year is always recorded at issuance and shown framing the central mark.
  • More rules incoming: tints, gradients, typographic treatments, color rules per category.

Anti-counterfeit stack (TBD — discuss one at a time)

  • HMAC signature in iframe URL, server-validated on every request. Tampered URL → 404.
  • Referer header binding — iframe URL signs against the client domain. iframe loaded from wrong domain → invalid-embed fallback.
  • Click target = verifier endpoint — clicking the badge takes the viewer to /verify/{user-slug}/{badge-instance}. The verifier URL and recipient @slug live in the click target, NOT in the rendered visual.
  • Public verifier endpoint — /verify/{user}/{badge-instance} returns JSON: { valid, granted_at, recipient, badge, year, revoked_at }.
  • Revocation propagation — revoked badges render "REVOKED" overlay; old screenshots stay; verifier reveals revocation.
  • Rate limit on enumeration — per-IP cap on /verify and /badge to slow scrapers.
  • Year-of-design freeze — old awards retain their original era-correct visuals.
  • Form-factor exclusivity (Tier A only) — Real Award badges only ever appear in their one exclusive portrait form factor; fakes in the wrong form factor self-identify as fake. (Tier B accepts wider tamper risk in exchange for distribution.)

Open design questions (one at a time, not all at once)

  • What artwork medium for the SVG — vector geometric? Multi-layer? Photographic-feel?
  • Is animation universal (every badge gets a subtle motion) or premium-tier only?
  • Per-form-factor minimum text — what fits in mini-chip 200×32 vs vertical-card 240×360?
  • Year split typography — same weight on left/right halves, or asymmetric (e.g., subtle on left, prominent on right)?
  • Tints, gradients, treatments — design language pending Aurora's customization of the Starter mark.
  • Do we ship APNG variants from day one, or only PNG until animation is locked?
  • How does revocation render visually (overlay? muted? "REVOKED" stamp?)?
